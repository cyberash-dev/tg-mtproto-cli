# Message

Представляет одно сообщение в чате.

## Поля

| Поле | Тип | Описание |
|---|---|---|
| id | number | ID сообщения (уникален внутри чата) |
| chatId | number | ID чата, которому принадлежит сообщение |
| senderName | string | Отображаемое имя отправителя |
| text | string \| null | Текстовое содержимое сообщения (null для чисто медийных сообщений) |
| links | readonly MessageLink[] | URL-сущности текста или подписи к медиа; пустой массив, если ссылок нет |
| date | Date | Дата и время отправки |
| media | Media \| null | Прикреплённое медиа (null если нет) |
| replyToId | number \| null | ID сообщения, на которое отвечает данное (null если не является ответом) |
| topicId | number \| null | ID forum-топика внутри chatId; null, если неприменим или не установлен |
| isOutgoing | boolean | Отправлено текущим пользователем |

## Контекст топика

Идентичность топика: `(chatId, topicId)`. `replyToId` остаётся ID непосредственного
ответа: ответ на корень и вложенный ответ могут иметь разные `replyToId`, но один
`topicId`. Нормализация выполняется общим mapper в infrastructure для всех путей
чтения сообщений, без дополнительных запросов истории или топиков.

| Метаданные сообщения | topicId |
|---|---|
| Подтверждённый supergroup-форум, topic header | `replyToTopId ?? replyToMsgId`, либо null, если оба отсутствуют |
| Обычное сообщение или обычный ответ в General без topic header | 1 |
| Сервисное создание топика в подтверждённом форуме | Собственный ID сообщения |
| Другое сервисное сообщение с topic header, включая переименование/закрытие | ID из заголовка |
| Другое сервисное сообщение без topic header | null |
| Не форум, недоступный peer или отсутствующий forum-флаг | null |
| Ответ/цитата с replyToPeerId другого чата в подтверждённом форуме | `replyToTopId ?? 1`; чужой replyToMsgId не используется |
| Скрытый источник без replyToPeerId, story/scheduled reply | null |

General присваивается только обычным сообщениям в подтверждённом форуме, а не
любому сообщению без topic header. Обычный discussion thread вне форума не является
топиком. Если peer полностью отсутствует в индексе mtcute, сохраняется ошибка
провайдера; дополнительные запросы для восстановления метаданных не выполняются.
Топики monoforum и новые bot-forum возможности не входят в этот контракт.

В читаемом выводе после ID сообщения появляется `[topic:42]`, когда ID известен;
для null маркер отсутствует. Имя можно получить отдельным `tg topics <chat>`:
сопоставить `topicId` с `id` в выдаче того же чата. По умолчанию возвращается до
100 топиков; при необходимости увеличить `--limit`. Переименование и закрытие
не меняют ID, закрытый топик остаётся читаемым. Отсутствие имени удалённого,
недоступного или не попавшего в выдачу топика не отменяет известный ID сообщения.

## Форматирование текста

Текст хранится как plain text. Форматирование (bold, italic, code, ссылки) при выводе в CLI отображается через ANSI-коды:

| Telegram-разметка | CLI-отображение |
|---|---|
| Bold | chalk.bold |
| Italic | chalk.italic |
| Code | chalk.bgGray |
| Pre (code block) | отображается как есть с отступом |
| Link | текст + URL в скобках, если URL не совпадает с подписью |

## Ссылки

`text` сохраняется без изменений. JSON содержит нормализованный массив `links`:

| Поле MessageLink | Описание |
|---|---|
| kind | `url` для видимого URL, `text_link` для ссылки с подписью |
| offset, length | Положение и длина в единицах UTF-16 исходного `text` |
| text | Текст соответствующего диапазона |
| url | URL из диапазона для `url`, скрытая цель для `text_link` |

Порядок сущностей и повторные вхождения сохраняются. URL не нормализуются и не
извлекаются регулярным выражением. Остальные сущности форматирования не входят в
`links`. Некорректные диапазоны ссылок (нецелые, отрицательные, нулевой длины или
выходящие за границы текста) пропускаются с предупреждением в stderr:
`Skipping invalid link entity: messageId=<id> offset=<offset> length=<length>`.
Сообщение, его исходный текст и остальные корректные ссылки сохраняются.
Предупреждение остаётся текстовым и при `--json`; stdout содержит только JSON-результат.

В терминале скрытая цель добавляется после подписи: `runbook (https://example.com/runbook)`.
Если подпись уже совпадает с URL, цель повторно не выводится. Подписи к медиа
обрабатываются так же. Управляющие символы в добавляемых URL отображаются как
`\uXXXX`; URL не открываются и не превращаются в управляющие последовательности
терминала. Рендеринг не меняет исходный `text` и диапазоны в `links`.
