# Message

Представляет одно сообщение в чате.

## Поля

| Поле | Тип | Описание |
|---|---|---|
| id | number | ID сообщения (уникален внутри чата) |
| chatId | number | ID чата, которому принадлежит сообщение |
| senderName | string | Отображаемое имя отправителя |
| text | string \| null | Текстовое содержимое сообщения (null для чисто медийных сообщений) |
| links | readonly MessageLink[] | URL-сущности текста или подписи к медиа; пустой массив, если ссылок нет |
| date | Date | Дата и время отправки |
| media | Media \| null | Прикреплённое медиа (null если нет) |
| replyToId | number \| null | ID сообщения, на которое отвечает данное (null если не является ответом) |
| isOutgoing | boolean | Отправлено текущим пользователем |

## Форматирование текста

Текст хранится как plain text. Форматирование (bold, italic, code, ссылки) при выводе в CLI отображается через ANSI-коды:

| Telegram-разметка | CLI-отображение |
|---|---|
| Bold | chalk.bold |
| Italic | chalk.italic |
| Code | chalk.bgGray |
| Pre (code block) | отображается как есть с отступом |
| Link | текст + URL в скобках, если URL не совпадает с подписью |

## Ссылки

`text` сохраняется без изменений. JSON содержит нормализованный массив `links`:

| Поле MessageLink | Описание |
|---|---|
| kind | `url` для видимого URL, `text_link` для ссылки с подписью |
| offset, length | Положение и длина в единицах UTF-16 исходного `text` |
| text | Текст соответствующего диапазона |
| url | URL из диапазона для `url`, скрытая цель для `text_link` |

Порядок сущностей и повторные вхождения сохраняются. URL не нормализуются и не
извлекаются регулярным выражением. Остальные сущности форматирования не входят в
`links`. Некорректные диапазоны ссылок (нецелые, отрицательные, нулевой длины или
выходящие за границы текста) вызывают `RangeError` с сообщением
`Invalid link entity range in message #<id>: offset=<offset>, length=<length>`.

В терминале скрытая цель добавляется после подписи: `runbook (https://example.com/runbook)`.
Если подпись уже совпадает с URL, цель повторно не выводится. Подписи к медиа
обрабатываются так же. Управляющие символы в добавляемых URL отображаются как
`\uXXXX`; URL не открываются и не превращаются в управляющие последовательности
терминала. Рендеринг не меняет исходный `text` и диапазоны в `links`.
