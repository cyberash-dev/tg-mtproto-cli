# Messages List

Выводит список сообщений из указанного чата.

## Команда CLI

```bash
tg messages <chat> [-n <count>] [--all] [--topic <id>] [--filter <kind>] [--query <text>] [--from <peer>] [--after <datetime>] [--before <datetime>]
```

## Входные параметры

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| chat | string/number (аргумент) | — | Идентификатор чата: числовой ID, username или @mention |
| -n | number (флаг) | 100 | Количество последних совпадений после всех фильтров; неотрицательный safe integer |
| --all | boolean (флаг) | false | Все совпадения в заданном чате/топике/диапазоне дат; приоритет над -n |
| --topic | number (флаг) | — | ID forum-топика (для супергрупп-форумов). Получить ID: `tg topics <chat>` |
| --filter | MessageFilter (флаг) | — | Одна категория: `url`, `photo`, `video`, `photo-video`, `document`, `gif`, `voice`, `audio`, `video-note`, `pinned` |
| --query | string (флаг) | — | Серверный поиск текста Telegram; непустой запрос |
| --from | string (флаг) | — | ID или username отправителя; резолвинг через mtcute |
| --after | string (флаг) | — | Включительная нижняя граница: `date >= after` |
| --before | string (флаг) | — | Исключительная верхняя граница: `date < before` |
| --account | string (глобальный флаг) | default | Alias аккаунта |

## Выходные данные

Список сообщений в хронологическом порядке (от старых к новым):

```
[2026-02-22 10:15] #42 Иван Иванов:
  Привет! Как дела?

[2026-02-22 10:16] #43 Пётр Петров:
  > Привет! Как дела?
  Всё хорошо, спасибо!

[2026-02-22 10:17] #44 Пётр Петров:
  [Photo]
```

В JSON-режиме (`--json`):

```json
[
  {
    "id": 42,
    "chatId": -1001234567890,
    "senderName": "Иван Иванов",
    "text": "Привет! Как дела?",
    "links": [],
    "date": "2026-02-22T10:15:00Z",
    "media": null,
    "replyToId": null,
    "isOutgoing": false
  }
]
```

Скрытые и видимые URL сохраняются в `links`, включая ссылки в подписях к медиа.
Например, для текста `See the runbook` со ссылкой на слове `runbook` поля имеют вид:

```json
{
  "text": "See the runbook",
  "links": [
    { "kind": "text_link", "offset": 8, "length": 7, "text": "runbook", "url": "https://example.com/runbook" }
  ]
}
```

В терминале: `See the runbook (https://example.com/runbook)`. Полный контракт
диапазонов и отображения описан в [Message](../entities/message.md).

## Основной сценарий

1. CLI проверяет обязательный непустой чат, категорию, количество, положительный
   int32 ID топика, непустые query/from и даты. При двух границах требуется `after < before`.
2. При `-n 0` без `--all` вернуть пустой результат до обращения к аккаунту или Telegram.
3. Определить активный аккаунт, загрузить сессию и подключиться через TelegramGateway.
4. Передать фильтры в `getMessages`. Числовые строки chat/from адаптер преобразует
   в числа, username резолвит mtcute. Чат присутствует в каждом запросе.
5. При наличии topic/filter/query/from использовать `searchMessages`; категория,
   текст, отправитель, топик и даты применяются на сервере и сохраняются на каждой
   странице. Обычное чтение и чтение только по датам используют `getHistory`, без
   пустого запроса поиска с пустой категорией.
6. Загружать от новых к старым страницами не более 100 или оставшегося N. Начальная
   позиция истории устанавливается возле `before`; история не сканируется вперёд
   от `after`. Продолжать по возвращённому `next`, в том числе после коротких страниц.
7. Применить точные границы дат, исключить дубли ID. Отброшенные записи не расходуют N.
   Остановиться при N совпадениях, пустой странице/отсутствии курсора или достижении
   нижней границы. Неубывающий курсор означает ошибку, частичный JSON не возвращается.
8. Преобразовать сообщения общим mapper, включая `links` и метаданные вложений.
   В mtcute GIF и видеосообщение представлены как video: `isAnimation` отображается
   в `animation`, `isRound` в `video_note`. Бинарные вложения не загружаются.
9. Один раз развернуть результат в хронологический порядок, отключиться и вывести.

## Даты и ограничения

Оба флага принимают `2026-02-22` (полночь UTC, прежняя семантика),
`2026-02-22T10:00` и `"2026-02-22 10:00"` (локальная зона системы), `10:00`
(сегодня в локальной зоне). ISO-время поддерживает секунды, доли секунды (до трёх цифр) и зону
`Z` или смещение `+03:00`. Невозможные даты и время отклоняются, а не нормализуются.
Telegram хранит секунды, но дробные границы выбирают точный интервал.

Для search нижняя серверная граница исключительна: адаптер передаёт
`ceil(after_ms / 1000) - 1`, верхняя: `ceil(before_ms / 1000)`.
В mtcute эти значения передаются как Date, а в history offset.date как секунды.
Вне положительного int32 серверная граница опускается, чтобы нормализация mtcute
не переполнилась; точная проверка дат остаётся в адаптере. Интервал, заканчивающийся
не позже Unix epoch, пуст: чтение истории не выполняется.

`--all` загружает все совпадения в память и может быть дорогим. Категории и текстовый
поиск определяются Telegram: `document` означает обычные файлы, `gif` включает
анимированные MP4. Допускается одна категория; `photo-video` является готовой
комбинацией. Глобальный поиск, произвольные комбинации, фильтры MIME/имени файла/
домена, автоматическое скачивание и переходы по ссылкам не поддерживаются.

## Ошибки

| Ситуация | Сообщение | Exit code |
|---|---|---|
| Не указан чат | `error: missing required argument 'chat'` | 1 |
| Неверная дата `--after`/`--before` | `Invalid date format or value. Use: YYYY-MM-DD, YYYY-MM-DDTHH:mm[:ss[.sss]][Z\|±HH:mm], or HH:mm` | 1 |
| Равные/обратные границы | `--after must be earlier than --before` | 1 |
| Некорректные count/topic/filter, пустой chat/query/from | Ошибка с названием параметра | 1 |
| Курсор не продвинулся назад | `Telegram pagination did not advance` | 1 |
| Ошибка резолвинга отправителя или сети | Исходное сообщение mtcute | 1 |
| Топик не найден | `Topic #42 not found in this chat` | 1 |
| Чат не является форумом | `Chat is not a forum. Remove --topic flag.` | 1 |
| Чат не найден | `Chat "xxx" not found` | 1 |
| Не задан default-аккаунт | `No default account. Use 'tg default <alias>' or --account flag.` | 2 |
| Сессия истекла | `Session expired for "work". Run 'tg auth' to re-authenticate.` | 2 |

## Граничные случаи

- `--all` для чатов с большой историей: выводить прогресс загрузки `Loading messages... 1500 loaded`.
- Сообщение-ответ (reply): отображать цитату оригинального сообщения с `>`.
- Сообщение только с медиа (без текста): отображать плейсхолдер `[Photo]`, `[Document: file.pdf]` и т.д.
- `-n 0`: вывести пустой результат без ошибки.
- Удалённые сообщения: пропускать, не выводить.
- Forum-топик: `tg messages --topic 42 -- -1001234567890` — загрузить сообщения из топика #42. Для получения списка топиков: `tg topics <chat>`.
- `--after "10:00"` — показать сообщения за сегодня с 10:00.
- `--after 2026-02-22` — показать сообщения с 00:00 UTC 22 февраля.
- `--after` + `-n` — сначала применяется фильтр по дате, потом лимит (показать последние N сообщений после указанного времени).

При `--json` ошибки аргументов и выполнения выводятся одной JSON-строкой в stderr:
`{"error":"message","code":1}`. Код совпадает с кодом завершения процесса (1 или 2),
ANSI-коды удаляются. Успешный stdout содержит только JSON-массив, прогресс отключён.
